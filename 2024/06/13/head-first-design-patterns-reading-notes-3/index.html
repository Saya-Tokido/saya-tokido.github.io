Introduction

If you want to design a Catering system.

First a customer order a rice, you create a rice class

then customer order a chicken, you create a chicken class, then add it to rice class

then customer order a soup, you create another class soup,and add it to rice class too

once again the customer order new meals,you need to create new class and add it to rice.

It seems inevitable, and how do description method and cost method ?

you may think add a new method to rice class,once a new instance added to rice, change the description and cost.

It’s a solution, but the following section introduce a better soluton.

Decorator pattern

First we create a abstract class Lunch

then let Rice class extends it

create a abstract class AbstractDecorator which extends Lunch

once you want to add meals,let it extends AbstractDecorator

soup is same

Since AbstractDecorator has a instance lunch and extends lunch,it can be warpped up again and again

that means,when you need to add a new meal, just let it wrap the former meal

Advantage of Decorator pattern

Decorator pattern adheres to the open/closed principle (open for extension, closed for modification), don’t need to change the former instance,it enhance the former class by wrap.
